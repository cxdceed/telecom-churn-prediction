# Data dictionary

> **All data is synthetic**, generated by `src/generate_data.py` (seed 42). Snapshot date: **2025-12-31**.
> The target is whether the customer cancelled in the 30 days after the snapshot.

## `customers.csv` (raw; 50,150 rows incl. 150 injected duplicates)
| Column | Type | Description |
|---|---|---|
| customer_id | str | Unique ID (`C100000`...) |
| signup_date | date | Snapshot minus tenure |
| tenure_months | int | Months as a customer (1-96) |
| age | float | Age in years; ~3% missing, ~0.3% impossible values (-1, 0, 999) injected |
| region | str | Northeast, Southeast, Midwest, Southwest, West |
| region_type | str | Urban / Suburban / Rural (casing and whitespace noise injected) |
| plan_type | str | Basic, Standard, Premium, Unlimited |
| contract_type | str | Month-to-month, One year, Two year (label variants injected) |
| num_lines | int | Lines on the account (1-5) |
| monthly_charge | float | Current monthly plan charge in USD; ~0.5% missing |
| has_streaming_addon / has_intl_addon | 0/1 | Add-on flags |
| autopay | 0/1 | Automatic payment enabled |
| payment_method | str | Credit card, Bank transfer, Debit card, Mailed check; ~1% missing |
| paperless_billing | 0/1 | Paperless billing |
| device_financing_months_left | int | Remaining device instalments (0 = none) |
| competitor_promo_active | 0/1 | Competitor promotion active in the customer's region |
| recent_price_increase | 0/1 | Price increase applied in the last 90 days |

## `billing_history.csv` (300,000 rows; 6 months x 50,000 customers)
| Column | Description |
|---|---|
| customer_id, billing_month, month_index | `month_index` 0 (oldest, Jul-2025) to 5 (Dec-2025) |
| plan_charge | Recurring plan charge (reflects a ~7% increase for `recent_price_increase` customers) |
| overage_charge | Overage fees from usage above plan cap (capped at $60) |
| billed_amount | plan_charge + overage_charge |
| data_gb_used | Monthly data usage in GB |
| paid_late / days_late | Late payment flag and days late |

## `support_tickets.csv` (~56,000 rows; 180 days before snapshot)
| Column | Description |
|---|---|
| ticket_id, customer_id, created_date | Identifiers and creation date |
| category | billing_dispute, network_quality, device_issue, plan_change, general_inquiry |
| resolved | 1 if resolved by snapshot |
| resolution_hours | Hours to resolve (missing if unresolved) |
| csat_score | 1-5 survey score (present for ~60% of resolved tickets) |

## `churn_labels.csv` (50,000 rows) - **target table, kept separate to prevent leakage**
| Column | Description |
|---|---|
| churned_30d | **Target.** 1 = cancelled within 30 days after the snapshot (rate ~7.9%) |
| churn_date | Cancellation date (blank if retained). **Never used as a feature.** |

## `model_table.csv` (processed; 50,000 rows x 39 columns) - engineered from the tables above
| Feature | Definition |
|---|---|
| late_payments_6m, avg_days_late | Count of late payments / mean days late over 6 months |
| avg_overage_6m, months_with_overage | Mean overage fee; months with any overage |
| data_gb_avg_6m, data_gb_volatility | Mean usage; coefficient of variation |
| data_gb_baseline_3m / data_gb_recent_2m | Mean usage in months 0-2 / months 4-5 |
| usage_change_60d_pct | (recent_2m / baseline_3m - 1) x 100 - **key leading indicator** |
| charge_change_6m_pct | Plan-charge change from month 0 to month 5 |
| tickets_30d / 90d / 180d | Ticket counts in windows ending at the snapshot (0 if none) |
| billing_tickets_90d, network_tickets_90d | Category-specific counts |
| unresolved_tickets, avg_resolution_hours, avg_csat, days_since_last_ticket | Support-experience features (missing when no tickets) |
| ticket_spike_ratio | tickets_30d relative to the prior 150-day run-rate |
| charge_per_line | monthly_charge / num_lines |
| churned_30d | Target |

## Planted relationships (so results can be sanity-checked)
Risk **up**: month-to-month contract, short tenure, high charge, late payments, competitor promo, recent price increase, bill shock (overage-prone),
rural, age < 30, high ticket propensity. Risk **down**: autopay, multiple lines, device financing, longer contracts.
Leading indicators: ~55% of churners show a usage drop in the last 60 days and ~50% a ticket burst in the last 30 days; some non-churners
show decoy dips/bursts. Unobserved noise (sd = 1 on the logit scale) caps achievable accuracy.
